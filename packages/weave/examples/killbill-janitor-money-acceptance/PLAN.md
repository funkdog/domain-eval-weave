# 任务选择与对照方案：维护 Janitor 的金额／币种验收

**当前改为“原始资料＋旧验收”与“相同基础＋既有领域知识包”的消费对照；旧格式比较停用。**
信息差异与结果要求见 [INFORMATION-LEDGER.md](INFORMATION-LEDGER.md)。原作者校准和旧材料历史见
[PREPARATION.md](PREPARATION.md)，不改写其结果。本文件属于组织者材料，
不是公共 API、冻结执行合同或向消费者提供的评分答案。共同任务说明见 [TASK.md](TASK.md)。

## 一页决策

| 项目 | 本次选择 |
| --- | --- |
| 真实需求 | 本项目现有 Janitor 验收只传入明确的插件金额和币种，需要检查其未覆盖的字段缺省与来源选择行为 |
| 消费者 | 维护验收代码的人或新上下文 Agent；不是再次修复支付组件的 Coding Agent |
| 交付 | 可运行的 Java 验收扩展、来源解释、逐项断言与未覆盖边界；不接受只有决策 JSON 的交付 |
| 复用知识 | 同一 Kill Bill 候选包中的 RequestedMoney／ProcessedMoney、状态映射、恢复更新条件和账户锁边界 |
| 本轮可检验问题 | 同一简短新需求下，已有领域知识包是否帮助新上下文消费者交付正确验收，并减少重新查证或需要补充的背景；单例不证明稳定收益 |
| 对照 | 相同原始资料、源码、旧验收、工具和预算；知识包组额外获得选题前已有的 Module 与人读模型，不提供选题后答案 |
| 不扩张 | 不换领域／Harness，不部署 SQL、Provider 或整个 Kill Bill，不改业务规则，不重跑旧题模型 |
| 当前状态 | 完成导向新pair已冻结并检查通过。operator要求宪宪亲自执行，旧委派已撤回；本人启动A被托管额度429拒绝，模型尚未启动。无需重做实验准备，等调度可用后由本人继续 |

这是**作者发现的本项目验收维护需求**，不是新的上游 bug、外部客户已提出的需求或版本变更。
选择它是因为有现成代码与明确覆盖缺口，不是因为已经知道领域表示会获胜。它也是作者按知识
相关性选择的单一案例，不能据此估计一般领域表示的平均收益。

## 1. 选择依据与静态证据

现有 [JanitorProbe](../../../../scripts/fixtures/JanitorProbe.java) 的五种场景都用 `TEN, Currency.EUR`
构造 Plugin 结果；[旧任务合同](../killbill-janitor-recovery/task-contract.json) 也仅包含这五种场景。
因而旧验证没有直接覆盖 Plugin 金额／币种为 null 时的选择分支。初版依据是静态覆盖判断；
后续无模型作者校准已确认：两个错误默认值版本在复用的旧五场景中均通过，但在新增金额场景失败。
这不改写旧题或证明所有缺省处理错误都能检出，原始记录见 [PREPARATION.md](PREPARATION.md)。

## 2. 范围、候选判据与交付

本任务固定现有 on-the-fly 恢复入口、内存 DAO、受控账户锁和依赖版本。使用未注入旧快照缺陷的
固定上游恢复类作为正确参照；旧题及其 digest／结果完全不改。消费者修改验收扩展，不修改该类、
真实 helper 或依赖。未来任务必须使用新的隔离工作区，不能将组织者目录交给消费者。

新增验收应覆盖以下区别；作者观察器已有执行结果，消费者交付与独立核验仍未发生：

1. Plugin 金额与币种都缺失，沿用**已有 processed 值**，不把 requested 值当默认值。
2. 金额与币种的缺失分别处理；一个字段存在，不代表另一个也存在。
3. 显式 Plugin 金额可以与 requested／已有 processed 值不同；显式零不等于缺失。
4. 已有 processed amount 为零，后续状态恢复成功，不代表已处理完整请求金额。
5. Plugin 仍给出同一 PENDING 状态，即使带来不同金额，也不能忽略本版本“同状态不更新”的条件。

金额使用十进制值比较；不因 `3.0` 与 `3.00` 的表示差异误杀。应选有来源支持的前置状态，
例如已有 PENDING 后转为 SUCCESS；不得为区分两种表示而默默引入不适用的业务状态。
本轮不承诺多币种处理是否合法，只描述固定实现的字段选择，必要的产品政策另列未知。

旧五场景作为不能破坏的回归边界；新增场景仅围绕上述区别，不扩成枚举组合穷举。
交付物：Java 验收代码／可应用补丁、必要的运行说明、规则到断言的映射和边界说明。
实际是否可编译、是否能拒绝错误实现，由独立的组织者执行链观察，不能用消费者自报分数代替。

## 3. 对照输入：明确知识包增加了什么

operator 于 `0001789043551170-000217-da920b14` 明确了减少新需求额外信息的价值，
并以 `0001789051392528-000240-dce5d5dd` 确认继续。此次不改变产品方向，只修正实验处理变量。

- A：固定原始 sources、正确组件源码、旧五场景的实际验收、相同依赖与开发指令。
- B：相同共同输入，加上任务选定前已有的领域 Module 与五份人读模型。
- 不再把整理好的知识先转成另一文件格式送给 A；A 可以正常检索来源、运行开发检查、自行做笔记。
- 按文件和信息项公开差异。B 的额外信息必须绑定选题前版本；新金额样本、标签和作者答案不给任一组。
- 不增加 B 专用工具；此次结果只能指向既有知识包的整体消费作用，不能单独归因于结构化／本体。
- 初版共同题面已经解释 requested／processed 区别。v2 对双方同时去掉这段重复背景，保留相同变更与安全要求。
  该调整显式记录在信息账中，不把已提供给双方的知识算作 B 独有贡献。

新入口接收 `src/JanitorProbe.java` 验收源码，冻结后在控制侧的正确／错误组件样本上重新编译并运行。
可信包装器区分正常返回、AssertionError 和无效执行；消费者不能用自报 JSON 或 System.exit 伪造完成。
非作者审阅指出，只有两个新金额反例会漏放“只写新检查、删掉旧回归”的提交；v2 加入旧冻结任务中的
旧快照错误，并增加 `money_checks_only` 对称负控。样本 fit 与说明存在分别报告，不自动标记完整交付；
旧回归范围和说明依据仍需独立源码／内容核验。
工作区之外的样本与标签不交给模型；实际运行目录使用无语义临时名，避免从路径读出样本标签。
私有文件读写拒绝已在无模型探针中核验；同 JVM 不是完整抗恶意字节码／反射攻击的资格证明。
正式模型工作区的隔离仍需在其入口中另行核验。

## 4. 测量、角色与停止条件

以下是设计期的指标出生证要点，未发放可行动资格：

| 字段 | 约定 |
| --- | --- |
| utility claim | 限本次简短需求与固定资料，记录既有知识包可用／不可用时的交付质量、检索负担与待确认信息差异；不自动等同结构化增益或净收益 |
| estimator | 分项记录正确参照／等价实现误拒、各类错误实现漏检、业务依据误用、运行有效性，以及实际用时／请求用量／人工介入；不合成总分 |
| validity bounds | 相同原始资料与预算、源码版本和观察面固定；额外整理知识正是处理变量；作者选题、公开知识与单例样本限制外推 |
| observer | 项目协调者读取原始工具／执行记录，不采用消费者自评作为事实 |
| domain owner | Kill Bill 维护者仅提供固定实现来源；其上游代码不自动成为本实验的独立校准者 |
| consumer | 本项目维护者与 operator 决定是否继续投入领域层，不自动晋升或部署 |
| calibrator | 待落实非作者的判据与观察面核验；不自称已经获得独立校准 |
| role overlap | 本轮作者同时选题、整理输入、拟订判据；有选题与确认偏差，只能形成探索设计 |
| repeatability | 启动前冻结 A/B 输入、共同题面、工具、模型配置、样本与预期；不同新上下文，禁止运行中补答案或为了改善结果重试 |

原先的小型配对试用设置各最多5分钟，两个限时轮次的结果已分别保留；它们不是本轮完成导向对照。
operator 在 `0001789093433167-000429-11b9616a` 明确“可以暂时不加上限，先验证我们的方向和价值”。
本轮因此改为A/B各一个全新上下文、同一模型／effort与安全边界，以自然结束并取得完整交付为目标，
不设人为任务时间截止、无自动重试。耗时／用量只作观察；不把旧的限时A和新不限时B拼成对照。
执行平台的单次托管限制与日志安全保护另列为基础设施边界，触发后保留中断，不记为业务失败。
准备、环境检查和失败判读不计入编码者的业务成绩；token 和工具次数只作成本分项，不用它们推断能力。
领域包已有建设成本、原始资料准备成本和未来更新成本分别记账，不能把 B 的知识准备当免费。
本轮不进行作者补答；只记录实际发生的输入和提出的澄清项，不能将未观察的用户补答量记为已节省。

采用正常参照、合理等价实现及小量定向错误实现建立判据；全通过／全拒绝／只断言状态等
投机验收器必须被识别。原始实现、人工真值与消费者输出分离：即使已有源码锚，也要先核验量尺，
不能用领域包或作者自己写的“应该通过”自证。具体样本与预期属于控制侧，消费者不可读取。

停止条件：

- 没有可靠判据、共同输入不一致、B 混入选题后答案、需要真实资金／生产数据或昂贵新依赖：不启动。
- 必须扩张到新的通用执行平台才能做：先收缩范围，不把本试验当扩平台的理由。
- 一组超时／环境无效：如实保留，不补跑“直到有结论”；不直接当另一组证明了业务优势。
- 小试有差异：只报告本任务的差异与可能解释；同域另一自然任务支持后才讨论迁移，不宣布一般收益。
- 无差异或 B 更差：保留零／负结果，不追加更难题来找正结果；可保留文档或简化表示。
